## 1. Mental Model: A Dictionary is a Contact List

You find a phone number by the person's **name**, not by its position. A dictionary works the same way: you look up a **value** by its **key**.

```python
message = {"role": "user", "content": "What is a cupcake?"}
print(message["role"])      # user
print(message["content"])   # What is a cupcake?
```

| | List (Lesson 2.2) | Dictionary (today) |
|---|---|---|
| Looks like | `["a", "b"]` | `{"key": "value"}` |
| Find an item by | Position: `items[0]` | Key: `info["name"]` |
| Best for | Things in order (chat history) | Labelled facts (a message, a product, a setting) |

## 2. Create and Read

```python
bakery = {
    "name": "Sweet Crumbs",
    "city": "Lahore",
    "hours": "9 am to 10 pm",
    "delivery": True,
}

print(bakery["name"])                      # Sweet Crumbs
print(bakery.get("phone", "not listed"))   # not listed (safe, no error)
print("city" in bakery)                    # True  (in checks the keys)
print(len(bakery))                         # 4
```

| Way to read | If the key is missing |
|---|---|
| `bakery["phone"]` | `KeyError`: the program stops |
| `bakery.get("phone")` | Gives `None` |
| `bakery.get("phone", "not listed")` | Gives your default |

**Pro habit:** use `.get()` with a default for anything that might be missing, like data from users or other systems.

---

## 3. Change a Dictionary

| Action | Code |
|---|---|
| Add a new key | `bakery["phone"] = "0300-0000000"` |
| Update a value | `bakery["hours"] = "10 am to 11 pm"` |
| Update several at once | `bakery.update({"city": "Karachi", "delivery": False})` |
| Delete a key | `del bakery["delivery"]` |
| Delete and keep the value | `hours = bakery.pop("hours")` |

Keys are **unique**. Setting a key that already exists **replaces** its value.

**See everything** (loops come in 2.4):

```python
print(list(bakery.keys()))     # ['name', 'city', 'phone']
print(list(bakery.values()))   # ['Sweet Crumbs', 'Karachi', '0300-0000000']
```

## 4. Nested Data: Lists and Dictionaries Together

Real AI data is **layers**: lists inside dictionaries, dictionaries inside lists. Read it one step at a time, from the outside in.

```python
business = {
    "name": "Sweet Crumbs",
    "prices": {"chocolate cake": 1500, "cupcake": 250, "brownie": 300},
    "best_sellers": ["chocolate cake", "brownie"],
}

print(business["prices"]["cupcake"])      # 250
print(business["best_sellers"][0])        # chocolate cake
business["prices"]["donut"] = 200         # add to the inner dictionary
print(len(business["prices"]))            # 4
```

```text
business["prices"]["cupcake"]
   |         |          |
   dict    inner dict   value: 250
```

**Your chat history is nested too:** a list of dictionaries.

```python
messages = [
    {"role": "system", "content": "You are a tutor."},
    {"role": "user", "content": "Hi"},
]
print(messages[-1]["content"])         # Hi  (last message, then its content)
messages[0]["content"] = "You are a pirate tutor."   # change the system message in place
```

**The AI response holds dictionaries too.** Now you can read the lines you copied in Lesson 2.1:

```python
print(response.usage_metadata)                    # {'input_tokens': 31, 'output_tokens': 42, 'total_tokens': 73}
print(response.usage_metadata["input_tokens"])    # 31
print(response.response_metadata["model"])        # llama3.2
```

`response` itself is an **object**, not a dictionary: read its answer with `response.text`, then use `[...]` on the dictionaries inside it.

## 5. Grounding: Give the AI Your Facts

Ask a model about a business it has never heard of and it will **invent** prices and hours. The fix: put the real facts **into the system message**.

```python
facts = {"name": "Sweet Crumbs", "city": "Lahore", "hours": "9 am to 10 pm", "cupcake": 250}

system = (
    f"You are the assistant of {facts['name']} bakery in {facts['city']}. "
    f"Opening hours: {facts['hours']}. Cupcake price: {facts['cupcake']} PKR. "
    "Only use these facts. If you do not know, say you will check with the manager."
)
```

| Without facts | With facts from a dictionary |
|---|---|
| "We are open 8 am to 8 pm." (made up) | "We are open 9 am to 10 pm." |
| "Cupcakes cost 150 PKR." (made up) | "Cupcakes are 250 PKR." |

**Quote habit:** inside an f-string that uses `"`, write keys with single quotes: `{facts['name']}`. Python 3.12+ also accepts `{facts["name"]}`, but older Python versions give a `SyntaxError`, so single quotes work everywhere.

This is the first step of **RAG** (giving the AI the right information before it answers), one of the most requested AI skills in industry.

## 6. Mini Build: Persona Bot with Real Facts

```python
"""Lesson 2.3: Bakery bot that uses real facts and can switch personality."""

from langchain.chat_models import init_chat_model

config = {"model": "llama3.2", "temperature": 0.3, "max_messages": 6}

facts = {
    "name": "Sweet Crumbs",
    "city": "Lahore",
    "hours": "9 am to 10 pm",
    "prices": {"chocolate cake": 1500, "cupcake": 250, "brownie": 300},
}

personas = {
    "friendly": "warm and cheerful, uses simple words",
    "formal": "polite and professional, no jokes",
    "sales": "excited, always suggests one extra item to buy",
}

# One config dictionary controls the model, so settings live in one place
llm = init_chat_model(config["model"], model_provider="ollama", temperature=config["temperature"])

# Facts go into the system message so the AI does not invent prices or hours
rules = (
    f"You are the assistant of {facts['name']} bakery in {facts['city']}. "
    f"Hours: {facts['hours']}. Prices in PKR: {facts['prices']}. "
    "Only use these facts. Answer in 2 short lines."
)

style = personas["friendly"]
messages = [{"role": "system", "content": f"{rules} Your style: {style}."}]

print("Bot ready. Commands: /persona friendly|formal|sales, /price <item>, bye")

while True:
    text = input("You: ").strip()

    if text.lower() == "bye":
        print("Bot: Goodbye!")
        break
    elif text.startswith("/persona "):
        name = text[9:].strip().lower()
        # .get with a default, so a wrong name keeps the bot working
        style = personas.get(name, personas["friendly"])
        messages[0]["content"] = f"{rules} Your style: {style}."
        print(f"Bot: Style changed to: {style}")
    elif text.startswith("/price "):
        item = text[7:].strip().lower()
        # Price questions are answered from the dictionary: free, instant, never wrong
        if item in facts["prices"]:
            print(f"Bot: {item.title()} costs {facts['prices'][item]} PKR.")
        else:
            print(f"Bot: Sorry, {item} is not on our menu.")
    else:
        messages.append({"role": "user", "content": text})
        messages = [messages[0]] + messages[1:][-config["max_messages"]:]
        response = llm.invoke(messages)
        answer = response.text
        messages.append({"role": "assistant", "content": answer})
        print(f"Bot: {answer}")
```

**Role play (do it in class):** ask "Do you have cupcakes?" three times, switching persona between each: `/persona friendly`, `/persona formal`, `/persona sales`. Same facts, three personalities. Then try `/price donut` and `/price Cupcake`.

## 7. Common Errors and Traps

| Problem | Cause | Fix |
|---|---|---|
| `KeyError: 'phone'` | Key does not exist | Use `.get("phone", default)`, or check with `in` first |
| `KeyError: 'Name'` | Keys are case-sensitive | Use the exact key: `"name"` |
| `AttributeError: 'dict' object has no attribute 'name'` | Wrote `bakery.name` | Dictionaries use brackets: `bakery["name"]` |
| `TypeError: 'AIMessage' object is not subscriptable` | Wrote `response["content"]` | The response is an object: use `response.text` |
| AI ignores your message | Key typo like `"Content"` or `"rol"` in a message | Message keys must be exactly `"role"` and `"content"` |
| AI still invents facts | Facts are not in the system message | Build the system message from your facts dictionary |

## 8. Job & Client Angle

- **All AI APIs speak dictionaries.** Requests, responses and settings are dictionaries (JSON). Reading nested data is a daily task.
- **Grounding is what clients pay for.** A bot that quotes the real price list and says "I will check" instead of guessing is a bot a business can trust.
- **Rules from data:** answering `/price` from a dictionary is free, instant and always correct. Use AI only where it adds value.

## Key Takeaways

- A **dictionary** stores values by **key**: `info["name"]`
- `.get(key, default)` reads safely; `in` checks keys; keys are unique and case-sensitive
- Real AI data is **nested**: read it from the outside in, `data["prices"]["cupcake"]`
- Every chat message is a dictionary with `"role"` and `"content"`; token counts live in `response.usage_metadata`
- **Grounding:** put real facts in the system message so the AI stops inventing them
